# Device/build helper scripts (Sprint-1 T2)

One usage line: set the environment (`DEVICE=<udid>`, and where relevant `BUNDLE_ID`, `TEAM_ID`, `IDENTITY`,
`XCENT`, `PROFILE`, `STIKDEBUG_BUNDLE_ID`, `AMETHYST_BUNDLE_ID`, `OUTDIR`, `DRY_RUN=1`) and run the script.

| Script | One-line usage |
|---|---|
| `sign_ipa.sh` | `BUNDLE_ID=... TEAM_ID=... IDENTITY=... XCENT=... PROFILE=... scripts/sign_ipa.sh App.app` |
| `install_device.sh` | `DEVICE=<udid> scripts/install_device.sh App.app [bundle-id-to-uninstall]` (add `DRY_RUN=1` to preview) |
| `push_jit_script.sh` | `DEVICE=<udid> scripts/push_jit_script.sh runtime/jit/amethyst.js` |
| `set_mc_options.sh` | `DEVICE=<udid> scripts/set_mc_options.sh` |
| `capture_device_logs.sh` | `DEVICE=<udid> OUTDIR=/tmp/vrmc-logs scripts/capture_device_logs.sh` |
| `build_provider.sh` | `scripts/build_provider.sh` — javac 25 + `jar` for the provider mod (no Gradle; classpath auto-resolved from Gradle caches + the Vivecraft tree); prints jar + sha256 |
| `build_bridge.sh` | `scripts/build_bridge.sh` — `MODE=device\|host\|both` (default device): clang cross-build + `vtool` visionOS retag; verifies platform/symbols |
| `stage_native_app.sh` | `scripts/stage_native_app.sh <VRMCShell.framework> [libvrmc_bridge.dylib]` — copy the EV-0086 app bundle, swap framework/dylib, embed profile, re-sign 169 Mach-O, `codesign --verify --deep --strict`; never installs (`DRY_RUN=1` preview) |
| `push_provider_jar.sh` | `scripts/push_provider_jar.sh [jar]` — `devicectl device copy to` the app data container `Documents/instances/default/mods/vrmc-provider.jar` + sha256 round-trip |

| `tests/DepthClearRegressionTest.sh` | `scripts/tests/DepthClearRegressionTest.sh` — regression guard for the M3c black-immersive root cause (EV-0093): default drawn-drawable depth clear must be 1.0, `vrmc-depth-zero.flag` A/B present, M3A probe reference 1.0 |
| `m3c_pull_and_check.sh` | `DEVICE=<udid> scripts/m3c_pull_and_check.sh` — pull the decisive M3c device logs/readbacks and print depthZero / scene-activation / first-presented-frame / parking triage (`--from <dir>` analyses an existing pull) |
| `m8_device_package.sh` | `scripts/m8_device_package.sh [--check] [--replace] [--zip]` — validate the staged M8 candidate (codesign + app-tree/provider hashes vs `export/m8-device-candidate.txt`) and copy it into the workspace `export/m8-device-package/` with `README.md`/`SHA256SUMS` (+ optional zip), so a device session no longer depends on volatile `/tmp` artifacts; exit 0 PASS / 2 validation or usage error / 3 exists without `--replace` |
| `m8_tuning_guide.py` | `scripts/m8_tuning_guide.py [--out FILE] [--print] [--logical WxH]` — regenerate `docs/mvp/M8_TUNING.md`: runs the host quality-ladder probe and combines its measured PSNR/acutance table with device-class (default 3660x3200 per eye) pixel budgets with/without SSAA, plus concrete A/B push-command recommendations; host proxy numbers, clearly labelled |
| `m8_device_report.sh` | `scripts/m8_device_report.sh --from <pull-dir> [--out FILE] [--operator-note "…"] [--evidence]` — build a human-readable device-session report from a pull: A6–A9 classifier output, key compositor/provider/shell lines, frame-trace summary, build identity, operator-statement placeholder and next steps; `--evidence` creates the evidence bundle (classifier + report + pulled logs). Works on simulator/fixture pulls for testing |
| `m8_device_session.sh` | `scripts/m8_device_session.sh prepare|collect|all [--dry-run] [--report] [--evidence] [--from <dir>]` — one-command M8 device session: validate the staged candidate hashes/codesign, install the app, push the matching provider jar, print the operator checklist (prepare), then pull + classify A6-A9 (collect; wraps m8_device_check.sh; `--report` also writes `export/m8-device-session-report.md`, `--evidence` bundles it). Exit 0 ok / 2 local artifact error / 5 device unavailable / classifier 0-4 |
| `m8_device_check.sh` | `DEVICE=<udid> scripts/m8_device_check.sh` — pull the M8 device logs and classify A6–A9 (foveation/rate maps, 4K-class logical size + provider eye targets, measured 90/120 Hz cadence + sharpening state, pacing): exit 0 PASS / 2 PARTIAL / 3 NOT RUN / 4 FAIL / 5 device unavailable; falls back to the `vrmc-status.json` render/pacing summary and the provider's `vrmc-m8-trace.csv` frame trace when logs rotated, and prints a frame-trace summary; `--from <dir>` analyses an existing pull or simulator case. Runbook: `docs/mvp/M8_DEVICE_RUN.md` |
| `tests/M8DeviceCheckTest.sh` | `scripts/tests/M8DeviceCheckTest.sh` — host test for the M8 classifier (synthetic PASS/90 Hz/old-build/FAIL log pulls; no device) |
| `runtime/probes/m8-quality-ladder/run.sh` | `runtime/probes/m8-quality-ladder/run.sh` — host Metal quality ladder: 1920×1080 reference box-downsampled to 0.4–1.0 eye-target scales, upscaled with the compositor's flat vs fovea-weighted sharp shader; measures PSNR and edge acutance per scale (7 checks: worst-case gap, identity no-op, acutance gain/bounded fidelity trade). Used to reason about blur/jaggedness and the device A/B (exit 0 PASS / 1 FAIL / 2 SKIP) |
| `runtime/probes/m8-foveation/run.sh` | `runtime/probes/m8-foveation/run.sh` — host Metal probe: the compositor's full-screen flat sampling math in a real variable-rasterization-rate (foveated) pass on macOS Apple Silicon (logical UV mapping + screen-size viewport convention) **and** the M8.6 foveated-sharpening upscale metrics (edge acutance, anti-halo bound, foveal weighting) and the combined foveated-drawable + sharpening pass; 14 checks (exit 0 PASS / 1 FAIL / 2 SKIP) |
| `m8_host_harness.sh` | `VIVECRAFT_REF=<tree> [TARGET_HZ=… CONTENT_FIRST=on|off DISPLAY_HZ=… SUPERSAMPLE=off|1.0..2.0 SOAK_SECONDS=…] scripts/m8_host_harness.sh [--timeout s]` — host Fabric harness: real Minecraft+Vivecraft client with the M8 provider, fake 3660×3200 display feedback through the real bridge; asserts the provider resizes its eye targets (1024×1024 → 1832×1600) and stays stable, and honours the M8 knobs (target cadence, content-first, simulated display cadence with guardrail revert) (host GL only; runbook docs/mvp/M8_HOST_HARNESS.md) |
| `push_m8_render_config.sh` | `DEVICE=<udid> scripts/push_m8_render_config.sh --eye-scale auto|0.25..1.0 --target-hz auto|60..120 --sharpening auto|off|0.05..1.0 --runtime-quality default|auto|0..1 --max-quality default|0.05..1.0 --content-first on|off --world-supersample off|1.0..2.0 --foveation-off` — push M8 rendering knobs to the app data container (`--print`/`DRY_RUN=1` preview, `--self-test` offline validation, 41 checks); see docs/mvp/M8_DEVICE_RUN.md §4 |

| `m3c_selfcheck.sh` | `scripts/m3c_selfcheck.sh [--fast]` — one-command M3c host/simulator self-check (depth regression, display-views, provider+bridge builds, bridge suite, provider-sampling harness) |

All are re-runnable. `sign_ipa.sh` re-signs every Mach-O in the bundle and embeds the profile;
`install_device.sh` retries installs and can uninstall a bundle id first.
