# M3c — window-parking vs immersive lifecycle probe (visionOS simulator)

Minimal native visionOS SwiftUI app that reproduces the VRMC shell architecture and measures, on the
**simulator**, what window "parking" does to the app/window-scene/immersive-space lifecycle, and whether
the CompositorServices presentation path itself works.

**Status:** simulator code/convention evidence only — NOT device evidence (AGENT.md §9, VERIFY.md §0.7).
Findings and the recommended `Shell.swift` change: [`docs/analysis/sim-lifecycle.md`](../../../docs/analysis/sim-lifecycle.md).

## What it is

- `WindowGroup` hosting a plain UIKit view controller via `UIViewControllerRepresentable` (mirrors the
  shell's `LauncherHostView`).
- `ImmersiveSpace(id: "m3c")` with a `CompositorLayer` (dedicated layout, foveation off, rgba16Float —
  the same `LayerRenderer.Configuration` the shell uses) rendering a bright animated red/green checker
  test pattern from a dedicated render thread (same loop structure as `VRMCCompositor.mm`:
  `waitUntilRunning` -> `queryNextFrame` -> timing -> `startSubmission` -> draw -> `endSubmission`).
- Full lifecycle logging to `Documents/sim-shell.log` + `NSLog`: every `UIApplication`/`UIScene`
  notification, SwiftUI `scenePhase`, 1 Hz `TICK` lines with app state + window dump
  (`isHidden`, `alpha`, `level`, `rootAlpha`, root class) + compositor frame count/state, exactly the
  state the shell needs in order to diagnose the device lifecycle.
- Optional second `WindowGroup(id: "second")` to separate "window scene deactivated" from
  "app backgrounded".
- Drawable-array diagnostics: `cp_frame_query_drawables()` count, per-drawable target
  (`builtIn`/`capture`), view/texture/depth/rrm counts, format/size, and the deprecated
  `cp_frame_query_drawable()` path, selectable at launch.

## Build / run

Prereqs: Xcode 27.x with the visionOS 27 simulator runtime, `xcodegen`, a booted simulator
(`VRMC-VP`, UDID `F025E133-019D-4811-944F-F3C8226E14CB`). All build output goes to `/tmp/m3c-build`.

```bash
cd runtime/probes/m3c-lifecycle-sim
./scripts/run-sim.sh                                  # build + all 13 parking variants (~7 min)
./scripts/run-sim.sh 03-hidden-open 05-alpha-firstframe   # selected variants only
./scripts/run-drawables.sh                            # drawable/capture probes (~4 min)
python3 scripts/summarize.py                          # results/summary.md
```

Raw commands (equivalent):

```bash
xcodegen generate
xcodebuild -project M3CProbe.xcodeproj -scheme M3CProbe -configuration Debug \
  -destination 'platform=visionOS Simulator,id=F025E133-019D-4811-944F-F3C8226E14CB' \
  -derivedDataPath /tmp/m3c-build CODE_SIGNING_ALLOWED=NO build
APP=/tmp/m3c-build/Build/Products/Debug-xrsimulator/M3CProbe.app
xcrun simctl install F025E133-019D-4811-944F-F3C8226E14CB "$APP"
xcrun simctl launch  F025E133-019D-4811-944F-F3C8226E14CB dev.vrmc.m3c \
  -M3CPark hidden -M3CParkWhen firstframe -M3COpenDelay 1.0
C=$(xcrun simctl get_app_container F025E133-019D-4811-944F-F3C8226E14CB dev.vrmc.m3c data)
cat "$C/Documents/sim-shell.log"
xcrun simctl io F025E133-019D-4811-944F-F3C8226E14CB screenshot /tmp/m3c.png
```

## Diagnostic arguments

| Argument | Values | Meaning |
|---|---|---|
| `M3CPark` | `hidden` (default; `isHidden=true` + `alpha=0`), `alpha` (`alpha=0` only), `tinyalpha` (0.01), `contentalpha` (root view alpha 0, window left visible), `contenthidden` (root view hidden), `transparent` (clear window background + content alpha 0), `none` | parking variant |
| `M3CParkWhen` | `open` (default), `firstframe` | park right after `openImmersiveSpace` or only after the first compositor frame |
| `M3CParkScope` | `all` (default), `main` | park all `windowApplication` scenes or only the main one |
| `M3COpenDelay` | seconds (default 1.0; `0` = at launch) | auto-open delay |
| `M3CSecondWindow` | 0/1 | open a second visible WindowGroup window |
| `M3CRestoreAfter` | seconds (<0 = never) | restore the parked windows |
| `M3CReopen` / `M3CReopenAfter` | 0/1 / seconds | dismiss + reopen the space (re-entry test) |
| `M3CAutoOpen` | 0/1 | control run without opening the space |
| `M3CDrawablesMode` | `all` (default), `first`, `builtin`, `legacy` | draw all `queryDrawables()` / only `[0]` / only `builtIn` target / deprecated `queryDrawable()` |

## Limitations

Simulator only (no device optics/tracking/compositor evidence); the simulator provides a single
`builtIn` drawable (no `capture` target, even while `simctl io recordVideo` runs), one view, no
rasterization-rate map, and it does not implement the device window/immersion background policy.
The probe app is not the shell (no modal game surface, provider bridge, JVM or Amethyst stack).
