# VRMC 1.4.1

Fix for the 1.4.0 report "when I turned off the VR mode and turned it on again, it seems crashed".

Status: host build and provider tests PASS, signed build installed on D1. **Not yet checked on the
headset** (VERIFY.md EV-0306).

## What happened

The game did not crash. Device log 2026-11-12 21:57 (HST): turning VR off in Minecraft ran the
provider's VR teardown, which always sent the "game stopping" signal. The launcher took that as the
game ending: it closed the immersive space and stopped waiting for game frames. Turning VR back on
started VR again in the game (it kept rendering at the title screen), but nothing reopened the
immersive space, so the headset showed no game.

## Fix

- The provider records why VR stopped in `vrmc-vr-state.txt`: `off` when VR is turned off while the
  game runs (Vivecraft's VR toggle), `exit` when the game is closing (Vivecraft tears VR down from
  `exitWorldAndClose`, after `Minecraft.stop()`), `on` after VR starts.
- On `off` the launcher keeps the game "running, VR off", shows "VR is off — turn VR on in Minecraft to
  come back", and re-enters VR by itself as soon as VR is on again and the game has a frame to show.
- Quitting the game and a game crash behave as before.

## Please check on the headset

Turn VR off in Minecraft, wait a few seconds, turn it back on: the game should come back in VR within
a few seconds.
