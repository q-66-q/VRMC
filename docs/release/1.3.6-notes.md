# VRMC 1.3.6 — menu cursor and bow

Operator test of 1.3.5 (2026-11-12): purple flash, head-turn smoothness, edges and the rest
**passed**; three items were open. Installed on D1 as 1.3.6; these fixes are host-tested only.

| Report | Root cause (device log 2026-11-12) | Fix |
|---|---|---|
| Head-ray cursor does not work in menus | Minecraft's mouse handler rescales cursor positions by the native game-surface size. VRMC measured that factor once when a menu opened (0.60), but it changed during the session (later 1.8). Every cursor write after that landed elsewhere: clicks at x=2680 on a 1280-wide screen. | Closed-loop cursor: every write is read back; if it is off, the factor is re-measured from that pair and the cursor is set again (converges in one step). Log: `cursor scale re-measured`. |
| Bow shot goes to the right | 1.3.5 aimed along the back-hand → front-hand line; with the bow held out in one hand and the draw anchored at the other cheek, that line points sideways. | Aim from the head through the bow (front) hand, i.e. where you point the bow. |
| Bow gesture should be the planned one | The engine also started a draw with open hands held apart and fired when either fist opened. | Plan (M7_GESTURES.md #9): **both fists** to draw, one hand in front (bow hand, fixed for the draw) and one behind; **opening the back fist fires**. Opening the front hand alone does not fire. |

Host: provider suite ALL PASS (bow tests updated to the plan: open hands do not draw, front-hand
opening does not fire, mirrored draw fires from the left back fist).
