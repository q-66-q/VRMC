# VRMC 1.3 release notes

Status: release candidate for the Apple Vision Pro D1 sideload build
(development signing, Apple Development team <TEAM_ID>).

## What this release is

VRMC 1.3 turns the app's flat window into a single native visionOS console and removes the
last two-UI behaviour: pressing Play starts Minecraft in place instead of jumping to the
Amethyst launcher screens. It also finishes the two 1.3 features - automatic setup and the
in-VR quick menu - and fixes device-found input and lifecycle defects.

## Highlights

### One window UI, one launcher
- The window is a native SwiftUI app with four tabs: **Play**, **Comfort**, **Controls**, **Help**.
  It replaces the developer overlay and the embedded launcher tab.
- **Play never switches screens.** The Amethyst launcher stays mounted in a hidden in-window host
  and its own Play button is pressed programmatically (the launcher keeps owning sign-in, Fabric,
  download and JIT). The visible state is the VRMC Play tab: "Starting..." until the game reports
  started, then the in-game actions card.
- Minecraft setup (Microsoft sign-in, Fabric profile install, JIT prompt) is a deliberate sheet,
  reachable from the Play setup card or Help only. It is never opened automatically.
- Comfort tab: seated play, snap/smooth turning, vignette, player height, world scale, render
  distance, thermal response. Controls tab: gesture reference + hand sensitivity. Help tab: live
  session status, diagnostics export, recovery actions.

### Automatic setup
- The VRMC provider mod ships inside the app and is installed/updated into the default Fabric
  instance at launch (hash-verified).
- Vivecraft 26.2-1.3.15 is downloaded from Modrinth with a pinned sha256 check, or imported from
  Files; duplicate Vivecraft jars block Play with a clear message instead of failing the game start.
- The Play card reports VRMC mod / Vivecraft / Fabric profile / Minecraft account / JIT status.
- A failed provider install cannot be masked by a stale file on disk.

### In-VR quick menu
- A normal Minecraft screen rendered on the in-world GUI panel, opened from the game menu's
  "VRMC Quick Menu" button or the launcher `quick-menu` command.
- Recenter, calibrate height, seated play, snap-turn step, vignette level, world scale, render
  distance, release stuck input, and a hands-only gesture guide.
- Settings the window also owns are written to the same files, so both surfaces agree after a
  session.

### Fixes
- Provider: posture-recovery baseline no longer learns the head drop from looking down, removing a
  false JUMP after mining/looking at the floor (with a regression test).
- Shell: crash-guard safe mode no longer suppresses the intended game start; clean-shutdown
  journal and diagnostics bundle retained; window parking/chrome behaviour unchanged from 1.2.
- Quick-menu and settings persistence hardened (atomic writes, bounds-checked parsing).

## Install / run

1. Install the signed app (dev profile provisions D1; profile expires 2026-11-15T03:21Z - re-sign
   before that date or the app will stop launching).
2. Open **StikDebug** and enable JIT for VRMC (script `amethyst.js`; the launcher keeps VRMC open
   and continues automatically once JIT is enabled).
3. Launch VRMC from the headset Home View (the host Mac's `devicectl process launch` is currently
   unreliable for any app on this pairing; launching from the headset is the supported path).
4. Press **Play**. First launch may download Minecraft/Fabric files; the window shows "Starting...".
5. Inside the world: left fist tap opens the game menu, which contains **VRMC Quick Menu**.

## Known issues / limits

- Custom immersive rendering is capped at 90 Hz by visionOS for this presentation path (M8 A8).
- A sub-1 s purple flash can appear on immersive menu/pause screens (cosmetic, M8).
- StikDebug has been observed being killed by the visionOS watchdog shortly after enabling JIT
  (93% CPU); the game continued in that session. If JIT does not attach, re-open StikDebug and
  retry.
- The development provisioning profile is short-lived (7 days). Re-sign with the current profile
  before installing; the app stops launching when the embedded profile expires.
- `devicectl device process launch` returns CoreDevice/Mercury transport errors for every app on
  this host/device pairing; use the headset Home View.
- The full M7/M8 device acceptance matrix is not re-run for this release; 1.3 changes are the
  window UI, setup and input fixes.

## Not in this release

- 120 Hz immersive rendering (platform-capped).
- Remaining M7 gesture-accuracy residuals listed in M7_ACCURACY_ITERATION.md.
