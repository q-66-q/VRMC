# VRMC 1.3.5 — rendering and bow fixes

Driven by the operator's 1.3.3/1.3.4 headset report (2026-11-12): jagged edges, head rotation not
smooth, a whole-scene purple glitch at the Minecraft start menu, and the bow not working.
Installed on D1 as an in-place upgrade (build 1.3.5). **Device behaviour is not yet verified** — the
fixes below are host-tested; each needs a headset check (see "Verify on the headset").

## Root causes and fixes

| Symptom | Root cause (evidence) | Fix |
|---|---|---|
| Head rotation not smooth | The compositor set the **newest** head pose on every drawable, but the picture it showed was rendered from an older pose (and repeated while the game ran below 90 fps). visionOS therefore never corrected it: the world swam with the head and snapped back. The game's frames carried no record of their pose. | The bridge stamps each published eye frame with the pose time the game rendered it from (`vrmc_eye_targets.presentation_deadline_ns`, 0 = unknown); the compositor keeps a 64-entry ring of the anchors it published and sets the **matching** anchor on the drawable, so visionOS reprojects every frame from its real pose. |
| Tearing / unstable picture, purple whole-scene flash at the start menu | The game rendered into the **same single texture per eye** the compositor was sampling, with no GPU sync (`syncValid=0` in the device log). After every eye-target resize the compositor could sample a brand-new texture nothing had been drawn into (undefined memory). The trace shows 4 resizes in the first seconds at the title screen. | Provider: each frame is GPU-copied into a **3-texture export ring** per eye (cleared to black when created) and that copy is published. Compositor: shows a frame only once it is **settled** (a newer frame exists, its GPU event signalled, or it aged 2 display frames). No resizes on the title screen (below). |
| Jagged edges | Minecraft has no MSAA; the game image is upscaled ~2x (and down to **4x** at scale 0.25, see below) and the old pass **sharpened** stair-steps. | Native-resolution **FXAA-style edge anti-aliasing** pre-pass (once per new game frame), then upscale; strong edges are no longer sharpened. Host GPU check: stair-step amplitude 1.04 → 0.76 output px (−27%) on a hard edge (`scripts/tests/compositor_shader_check.sh`). `Documents/vrmc-aa.txt` = `off` disables it for A/B. |
| Blurry/jagged for ~40 s after loading | Device trace: loading hitches (25–45 ms frames, CPU/IO bound) drove the auto resolution from 0.50 to **0.25** in seconds, then it crawled back over ~40 s (8+ resizes). | Auto floor 0.35 (explicit knob can still go lower); no resizes in the menu room; ~7 s settle after joining a world before judging performance. |
| 45 Hz lock | Device trace: the display cadence fell to 45 Hz, the policy took 45 Hz as its budget and **raised** resolution to 100% (4096×4096), keeping the session at 45 Hz for ~40 s. | Auto mode always budgets for at least 90 Hz (an explicit `vrmc-target-hz.txt` override is still honoured). |
| Bow does nothing | Vivecraft `bowMode=ON` (roomscale) only draws when its bow interact module sees one controller notched against the other at a fixed angle; hand-derived controller poses do not satisfy it, and the use key VRMC presses is ignored for bows in that mode. | VRMC sets Vivecraft's bow mode to **OFF** (plain hold-to-draw): the two-hand bow gesture holds use (draw) and releases (fire), and the shot is aimed along the line from the back hand to the front hand. `bow.mode=vivecraft` in `vrmc-input-tune.properties` keeps Vivecraft's mode. |
| Game crash on one bad tracking sample | `pollTracking` threw a fatal exception on the render thread for a zero/NaN head pose. | Keeps the last good pose, logs the first 5 occurrences. |

  menu-room resize, 7 s world settle).
- Bridge suite ALL PASS incl. the new pose-stamp check (stamp, explicit value wins, no timestamp leak).

## Verify on the headset

1. Start menu: no purple/garbage flash on VR entry or while the menu world builds.
2. Turn your head quickly in a world: the scene should stay fixed in space (no swimming/snapping).
3. Block edges at arm's length and in the distance: visibly smoother than 1.3.4.
4. Hold a bow (and arrows): hands apart = draw, open the back hand = fire; the arrow follows your hands' line.
5. After joining a world, the picture should not go noticeably blurrier during chunk loading.

`vrmc-compositor.log` now reports `edge anti-aliasing: ON`, `eye frames: showing settled frames only
... pose-matched anchors ON`, and periodic `pose-matched anchors: matched=… unmatched=…`; the provider
log reports `export ring: 3 x 2 eye textures` and `bow: Vivecraft bowMode ON -> OFF`.
