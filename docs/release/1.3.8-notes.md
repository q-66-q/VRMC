# VRMC 1.3.8 — arrow in the right hand, hotbar stays, radial menu on a fist hold

Operator feedback on 1.3.7 (2026-11-12): "good". Requested: the right hand should hold the arrow
while the bow is held; the hotbar must stay visible; add a right-fist hold that opens Vivecraft's
default shortcut (radial) menu. Installed on D1 as 1.3.8; host-tested only.

| Request / finding | Cause | Change |
|---|---|---|
| Right hand should hold the arrow | 1.3.7 put the bow in the left hand by swapping the two hand poses; the right hand then showed the (empty) off-hand item. | The pose swap is gone. `VRArmHelperMixin` uses Vivecraft's own roomscale-bow presentation (`VRArmHelper.getBowOverride`): the selected bow is drawn in the left hand and the arrow it would shoot in the right hand. While drawing, the right hand is empty, because the drawn bow model carries the arrow. A mirrored draw (right hand in front) shows the bow in the right hand. |
| Hotbar must stay visible | Vivecraft hangs the wrist hotbar off the left controller. The 1.3.7 swap moved it to the right wrist, and the bow grip roll rotated that controller. | The controllers are no longer swapped or rolled. The bow grip roll is applied to the bow model only (`VivecraftItemRenderingMixin`, tunes `bow.roll.left` / `bow.roll.right`). The touch hotbar is the right index on the left wrist again. |
| Right fist hold = shortcut menu | New gesture. | Hold the right fist still for 0.65 s (longer than any right-fist tap, so taps are unchanged) to open Vivecraft's radial menu (chat, commands and the other default entries). Point the fist at an entry and open the fist to choose it. A left fist (bow draw / inventory chord), losing right-hand tracking, or a screen opening closes the menu **without** choosing. Attacks are suppressed while the menu is open. Hold mode is forced only while VRMC holds the menu, and your own setting is restored afterwards. |
| (found) Place/break split mismatch | VRMC's action layer still split place/break at a hard-coded 350 ms; the gesture engine moved to 380 ms in 1.3.7. | Both use `VisionM7Gesture.PLACE_MAX_NS` (380 ms). |

Both mixins use `require = 0`, so a Vivecraft version mismatch cannot stop the game from
starting. VRMC logs `bow render hook ... did not run` if the bow hook is missing.
